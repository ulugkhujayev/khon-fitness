# Khon Fitness 0.4.7 user audit

Resume ongoing work from [QA-AUDIT-STATE.md](QA-AUDIT-STATE.md). It records the next small test batch and avoids repeating completed checks.

The published 0.4.7 APK has four confirmed defects in ordinary user flows. I fixed them in a local, signed 0.4.8 audit preview. This is **not** a complete Samsung Galaxy S25 certification: the S25 is not connected, and the available Android emulator does not run One UI or refresh at 120 Hz.

## Test setup and scope

- Published 0.4.7 APK SHA-256: `b3ed77524392af0cdeac81099046583049a7418f9695d844d2d5145d1d66dfbb`.
- Generic Android API 36 emulator, adjusted to 1080 × 2340 at 420 dpi to approximate the S25 viewport. Samsung lists the S25 display at 1080 × 2340 and up to 120 Hz: <https://www.samsung.com/uk/support/mobile-devices/what-are-the-differences-between-the-galaxy-s25-ultra-s25-plus-and-s25/>.
- Tested fresh data, preserved data after an upgrade, and a reset. UI evidence and the decision log are in `dist/qa-047-e2e/`. That directory and the preview APK are ignored by Git, so they are available in this checkout only.
- Android 9 observations were excluded from S25 acceptance. The stretch cue and Start button fit at the S25-sized viewport in [`37-s25-viewport-stretch.png`](../dist/qa-047-e2e/37-s25-viewport-stretch.png).

## Combined fix round

After the audit, the owner asked for every finding from both review threads to be fixed. The Codex thread's code review had found four spec gaps that the emulator crawl never reached. History drew one dot per date instead of one per session. The long-press and drag gestures for the day plan did not exist. A weekly-template edit rewrote the plan marks of past days. The cardio editor followed the current exercise fields; that one was already fixed. All three open gaps are now fixed. I tested the migration from database version 3 to 4 on the emulator's existing data, a drag swap, the long press into the plan sheet, and a template edit that left past Thursdays unchanged. [`202-history-swapped.xml`](../dist/qa-047-e2e/202-history-swapped.xml), [`205-history-past-kept.xml`](../dist/qa-047-e2e/205-history-past-kept.xml).

The running timer now survives process death. After `am crash` and after a force-stop, the interval timer came back with its elapsed time intact, and a discarded session left nothing to restore. An Opus review found a race: a timer screen that came back from Recents could start the workout again at 0:00. I fixed it by adopting the matching snapshot on start. [`210-timer-after-crash.xml`](../dist/qa-047-e2e/210-timer-after-crash.xml), [`212-timer-after-forcestop.xml`](../dist/qa-047-e2e/212-timer-after-forcestop.xml), [`213-no-ghost-restore.xml`](../dist/qa-047-e2e/213-no-ghost-restore.xml).

The stretch sheets now decode off the main thread into GPU memory. With the player open, native heap stayed at 21 to 25 MiB, where a single software sheet alone needs 50 MiB. The demo clock follows the display frame instead of a 40 ms delay. [`214-meminfo-player.txt`](../dist/qa-047-e2e/214-meminfo-player.txt).

The speech crash is not an app defect. A single cue with no Skip at all crashed `com.google.android.tts` with `SIGILL`, an illegal CPU instruction, in its synthesis thread on this emulator. The app now sends at most one cue per 300 ms anyway. [`216-single-cue-tts-log.txt`](../dist/qa-047-e2e/216-single-cue-tts-log.txt).

The figure now uses a white illustration style with a dark contour, muscle borders, soft grooves, and fiber lines inside the red targets. It reads as an anatomy figure rather than a mannequin, A second pass replaced scribbled back lines with trapezius, shoulder-blade, and latissimus borders, and gave the red targets rounded edges. It is still sparser than the reference, and the thighs stay under the shorts. [`222-final-art-hip.png`](../dist/qa-047-e2e/222-final-art-hip.png), [`06-final-4-poses.png`](../dist/art-review/06-final-4-poses.png).

The owner then reported that a strength workout recorded by the watch was imported as Norwegian 4x4. The importer maps a strength workout to no modality, and the default rule fell back to the first cardio exercise in the list, so "Import all" filed it without asking. Strength workouts from the watch are no longer imported, since gym sessions are logged in the app; the import screen says how many it left out. Other unmatched types, such as HIIT or walking, get no default exercise, and "Import all" skips them until the user picks one. Unit tests cover the rule; a real Mi Fitness import still needs a check on the phone.

Smaller fixes: choice rows report their checked state to TalkBack, the empty bodyweight reads "No entry yet", the window widget says "Tap to set hours" when off, both widgets have spoken labels, and a stretch run is saved only after one completed stretch or 30 seconds. Full lint now has no errors. The updater had asked for update ownership without the permission, so the request did nothing; the owner wants as few update steps as possible, so I removed the request rather than declaring the permission, which would add a confirmation to browser installs on Android 14+.

## Open checks before calling the S25 experience polished

The emulator cannot establish One UI insets, keyboard behavior, notification styling, widget appearance, battery impact, or 120 Hz smoothness on an S25. Its pooled frame report includes startup and navigation on software-rendered hardware, so [`perf-emulator.txt`](../dist/qa-047-e2e/perf-emulator.txt) is diagnostic evidence, not an S25 performance score. The animation clock currently ticks every 40 ms, or 25 Hz, and the stretch demonstration decodes a 4096 × 3200 bitmap; both deserve a real-device trace. A timer also keeps its active state in process memory, so interruption/recovery needs a physical-device check.

I saved a strength session with one completed set; a full 42-set workout remains untested. I did not complete a full uninterrupted timed stretch sequence, Health Connect with a provider, or a battery run; eating-window notification delivery passed only on the generic emulator. History still draws one dot for a day with several sessions; the date label now states the count for TalkBack, and the visual stays a design choice. The real S25 is the next gate for these checks and any release decision.
