## What this project is

A cross-platform React Native (Expo) rewrite of **Khon Fitness**, a
one-person gym, cardio and stretching log that exists today as a native
Android app: https://github.com/ulugkhujayev/khon-fitness (Kotlin, Jetpack
Compose, Room; owner Mirzohid). That repo is the source of truth for
behavior. Never push to it.

To read the original while porting:

```sh
git clone --depth 1 https://github.com/ulugkhujayev/khon-fitness.git ../khon-fitness
# screens:  android/app/src/main/java/dev/mirzohidkhon/khonfitness/ui/screens/
# widgets:  .../ui/components/   theme: .../ui/theme/Theme.kt   nav: .../ui/KhonNav.kt
# data:     .../data/ (Entities.kt, Repository.kt, Dao.kt, Stretching.kt, StretchDemo.kt)
# timer:    .../timer/ (TimerService.kt, TimerState.kt, CueGate.kt)
# tests:    android/app/src/test/java/...  mockup: mockup/   QA notes: docs/
```

## Decisions (settled with the user)

- Own private repo `MametovUral/khon-fitness-expo`, app at the repo root.
- Android and iOS are equal targets. No web target.
- UI language English only, as in the original (`docs/SPEC.md`).
- **Bun only**: `bun install`, `bun run …`, `bunx …`. Never npm/npx/yarn.
  Bun **1.4.2 or newer** (`packageManager`): `bun.lock` is lockfile v2, and
  Bun 1.3 cannot read it ("Unknown lockfile version"), ignores it and
  re-resolves to a different tree. Fix with `bun upgrade`, then
  `git checkout bun.lock && bun install --frozen-lockfile`.
- Package and bundle id `dev.mirzohidkhon.khonfitness.expo`, so it installs
  next to the Kotlin app.
- `android/` and `ios/` are generated by `bunx expo prebuild` **and
  committed** (user's request). **Never edit anything inside them**: the
  next `bunx expo prebuild --clean` wipes hand edits. Change `app.json` or a
  config plugin, then prebuild (rules in AGENTS.md, "Never edit `android/` or
  `ios/`").
  `pod install` runs on the Mac.
- `bun run ios` / `bun run android` are `expo run:ios|android`: they build the
  native project and open that build, never Expo Go. `bun run start` passes
  `--dev-client` for the same reason. Without it `expo start` targets Expo Go,
  because `expo-dev-client` is not installed. Prebuild did not rewrite these
  scripts itself: it only matches `expo start --ios` without `bunx`.
- `docs/SPEC.md` and `docs/DESIGN.md` (copied from the original) bind every
  screen: HIG dark palette, Inter, grouped inset lists, one primary button
  per screen, no captions or pill badges, number widget with − / + .

## Stack

Expo SDK 57, React Native 0.86, TypeScript strict, Expo Router (routes in
`src/app/`), expo-sqlite, expo-file-system (new `File`/`Paths` API),
expo-sharing, expo-document-picker, expo-crypto, expo-symbols,
expo-system-ui, react-native-svg (charts), react-native-keyboard-controller
(`KeyboardProvider` in the root layout; screens scroll with
`KeyboardAwareScrollView` so a focused field stays above the keyboard),
expo-audio (timer beeps from `assets/sounds`, made by `bun scripts/beeps.ts`),
expo-speech (spoken cues), expo-keep-awake (timer and stretch player),
expo-notifications (timer alerts while the app sleeps, eating-window
reminders), `expo-sqlite/kv-store` (the running timer's snapshot). The stretch
demonstrations are pre-rendered WebP sprite sheets in `assets/stretch_demos`
(see its README), shown with the plain `Image`.
Check the SDK 57 docs before using any Expo API (see AGENTS.md); do not
code Expo APIs from memory. ESLint 9 with `eslint-config-expo` (ESLint 10
breaks `eslint-plugin-react`); its React Compiler rules are on, so no ref
reads during render and no synchronous `setState` inside effects.

## Code map and conventions

- `src/theme/index.ts`: `K` colors, `Type` text styles, `Space`; same names
  and values as `Theme.kt`. Fonts load in `src/app/_layout.tsx`.
- `src/components/` (one exported component per file):
  - `ui/`: design-system primitives with a barrel `index.ts`: buttons
    (TextButton, PrimaryButton, Capsule, PlusButton, BarCircleButton), lists
    (GroupedList, ListRow, FieldRow, FieldValue, ToggleRow, Empty), inputs
    (NumberField, NumberRow, TimeStepper, InlineTextField, SearchField,
    Segmented, Toggle, DateRow, MonthGrid, MonthSwitcher), sheets (Sheet, ChoiceSheet,
    ChoiceList, ChoiceRow, SheetGroupTitle, ConfirmSheet), TitleRow,
    LineChart (`format` for m:ss), ProgressBar, Dot, Check.
    Pick lists use `ChoiceSheet`; do not build another sheet of choice rows.
  - `layout/`: NavBar, BackButton, EditorScreen (empty = loading frame),
    TabScreen, FloatingTabBar, `useLeaveWhenGone` (leave a screen whose record
    is gone).
  - Feature folders: `plan/` (WeekStrip, PlanItemSheet, DayPlanSheet for
    one date, `colors.ts`), `today/` (TodayCard, BodyweightSection,
    WindowSheet, `useNow` minute clock), `session/` (BlockCard, SetRow,
    SwapSheet, … and the hooks `useFieldFocus`, `useLeaveWhenGone`),
    `editors/` (ExerciseForm with a table-driven select config, ModalityForm,
    ColorSheet, BlockExerciseGroup), `history/` (CalendarGrid with the
    `useDayDrag` long-press drag, CalendarDay, DayDetail, BodyweightHistory,
    ExerciseProgress, MuscleVolumeList, CardioTrendsSection), `cardio/`
    (TimerView, CardioForm, CardioFieldRows, IntervalRows, ComputedRow),
    `stretch/` (StretchDemonstration: the lesson before Start and the
    clock-driven pose during it; DemoFrame shifts a whole sprite sheet inside a
    one-frame clip, so a new frame never decodes again; DemoPoster;
    `demoAssets.ts` with the literal requires; StretchPlayerView; StretchForm;
    RoutineOrderList).
- `src/timer/`: the running timer (TimerService.kt without the Android
  service), a cardio interval timer or a stretch routine. `engine.ts` owns the
  one timer: a 50 ms clock while the app is open, cues per transition, a
  snapshot per transition, and on going to the background it stops the clock
  and schedules the phase changes as notifications, cancelled on return. The
  end writes the cardio session's `timeSec`, or a StretchSession once the run
  counts (`stretchSessionFor`). `startStretch` gives each run the id
  `routineId:runId` and continues a run of the same routine; `skipTimer`.
  `sound.ts` (beeps, speech through `CueGate`, vibration), `snapshots.ts`
  (kv-store), `useTimer` (useSyncExternalStore).
- `src/alerts/`: `notifications.ts` (local notifications by kind, `timer` or
  `window`, each with its Android channel; schedule and cancel one kind
  without the other; `tappedAlert`), `windowReminders.ts` (`rescheduleWindow`
  schedules a week of boundaries and reminders; run at start, on return to
  the app, after every window change and after import or reset),
  `windowRequest.ts` (a tapped window notification opens the sheet on Today),
  `NotificationHost` (root layout: restore the timer, keep the window
  schedule current, open what a tapped notification belongs to).
- `src/navigation.ts`: `openSession` / `replaceSession` open a session in the
  screen `sessionScreen` (domain/plan.ts) picks: live session, timer or form;
  `openStretchPlayer`.
- `src/db/hooks.ts`: the named reads screens use (`useToday` with the active
  routine and the eating window, `useSession`, `usePreviousLogs`,
  `usePrograms`, `useProgram`, `useBlock`, `useLibrary`, `useModalities`,
  `usePlan`, `useExerciseUsage`, `useHistory`, `useCardioSession`,
  `useStretching`, `useStretchUseCount`).
- `src/domain/`: pure TypeScript, **no Expo or React imports**, so `bun test`
  runs it. `types.ts` (entities with Kotlin field names, `Defaults` = Kotlin
  constructor defaults), `dates.ts` (local `yyyy-MM-dd`, ISO weekday 1..7;
  never use UTC/`toISOString` for dates), `plan.ts` (`itemFor`, `PlanRules`),
  `session.ts` (`buildSetLogs`, `previousByKey`, `epley`), `workout.ts`
  (summary, block grouping and title, next pending set, gains, effort,
  Today's done line), `history.ts` (day dots, day labels, calendar hit test
  and drop rule, session lines, e1RM progress, weekly sets per muscle, cardio
  trends), `timer.ts` (TimerState, snapshot, CueGate, cue and alert rules,
  timer screen text), `cardio.ts` (form fields, values, pace, save patch),
  `editors.ts` (block/exercise editor rules, library filter, preset colors),
  `chart.ts` (chart scale and label picks), `stretch.ts` (the guides in
  `stretchGuides.json`, preview and exercise frames, `DemoClock`, routine
  steps and summary, player text, when a run counts, editor limits),
  `window.ts` (`EatingWindowRules`, the Today summary, the 28-day strip, hour
  limits, `windowAlerts`), `format.ts` (`fmt`, `parseNumberInput`, `dur`,
  `preview`), `backup.ts` (`parseBackup`, `describeBackup`), `seed.ts`.
- `src/db/`: `schema.ts` (Room v4 DDL verbatim, 17 tables, `COLUMNS`,
  `BOOL_COLUMNS`), `rows.ts` (bool 0/1 conversion, upsert SQL),
  `database.ts` (`getDb` with `PRAGMA user_version` migrations, `all`/`first`/
  `count`, `write(tx => …)` = serialized transaction queue that notifies
  table listeners), `useLive.ts` (hook that re-runs a query when its tables
  change; the Room `Flow` equivalent), `repository.ts` (port of
  `KhonRepository`), `backupFile.ts` (share sheet export, picker import),
  `DataProvider.tsx` (opens + seeds before screens render; hides splash).
- All writes go through `write()`; screens read with `useLive(query, tables)`.
  Live edits use the column-level `patch*` functions (`patchSetLog`,
  `patchSession`, …), so a screen holding an older row never writes back a
  field it did not change.
- Text and number fields keep their own text while focused; outside values
  land only when not focused, so a database round trip never moves the cursor.
- Sheets take `visible` and slide out after it turns false; callers keep the
  data the sheet shows (an `open` flag next to the data, not data = null).
- Editors with a draft split into a loader and a form keyed by id; the form
  takes its initial draft in `useState`, never from an effect.
- Ids: `newId()` in `src/db/id.ts`, 8 hex chars like Kotlin.
- Backup JSON keys match the Kotlin `Backup` class, both directions.
  Missing keys take Kotlin defaults on import (kotlinx omits defaults).
- New logic goes in `src/domain` with a `bun test` case in `tests/`. Port the
  matching Kotlin unit test when one exists.
- Code quality bar (reusable components, thin route files, hooks for data,
  theme tokens, strict types): AGENTS.md, "Code quality". It binds every
  change.

## Stages

0. **Done.** Expo base: tabs, theme, shared components.
1. **Done.** Data layer: schema, repository, seed, backup import/export,
   Settings screen (export, import with merge/replace, reset). Today shows the
   resolved item for today; Programs lists programs and the library rows.
   Native projects prebuilt and committed.
2. **Done.** Gym: Today (week strip, plan sheet with override and back to
   template, Start / Resume / done line with Start again, bodyweight chart and
   add field), live session (`session/[id]`; also the read-only view with
   Edit for a finished session), program, block, exercise and modality
   editors, exercise library, week plan. Cardio items show Start disabled
   until stage 4 (there is no cardio screen yet).
3. **Done.** History: month calendar with session dots, a changed-plan mark
   and the plan as a faint dot; tap selects a day, long press opens its
   plan, drag onto a day ahead swaps the two (screen readers get the same as
   custom actions); the day's sessions and stretch runs; stretching in the
   month; bodyweight chart; e1RM chart and top sets per exercise; sets per
   muscle this week and last; cardio trends (pace, heart rate, interval heart
   rate, time). The Kotlin Import button (Health Connect) waits for stage 6.
   Cardio rows in the day list open nothing until stage 4.
4. **Done.** Cardio: the form (`cardio/[id]`: date, the exercise's fields,
   pace, one row per work interval, effort, note; Save / Discard) and the
   interval timer (`timer/[id]`: phase colors, 3-2-1 start, three beeps
   before each change, spoken cues, long beep at the end, screen kept on,
   Stop writes the time so far). Today starts and resumes cardio, History
   opens cardio sessions. TimerStateTest, TimerSnapshotTest and CueGateTest
   are ported. Not like Kotlin: no lock-screen notification with Pause and
   Stop and no Android foreground service; while the app sleeps the phase
   changes arrive as scheduled notifications (one sound each, not the three
   beeps), and the state catches up from the wall clock on return. Pulling
   headphones does not pause. The expo-notifications plugin adds the iOS push
   entitlement (`aps-environment`), which a free Apple team cannot sign.
5. **Done.** Stretching and the eating window. Today shows the active
   routine (green once stretched today) and the eating window ("closes in
   2 h 10 m", "opens 12:00", "Off"). The player (`stretch/[routineId]`): a
   ready screen per stretch and side with the guide playing its steps (step
   tabs, Play/Pause demo, Change view), Start with 3-2-1, the held pose or
   reps following the clock, Pause/Resume, Skip, Stop; black while waiting,
   green while stretching; the end records the run and goes back. Programs →
   Stretching (`stretching`): routines (one active), the routine editor
   (`routine/[id]`: name, active, seconds per stretch, order, add, delete),
   the stretch library (`stretches`) and editor (`stretch-editor/[id]`). The
   window sheet: Open now / Close now, Opens / Closes in 15-minute steps,
   Remind before, On, the last 28 days. StretchDemoTest, DemoClockTest and
   StretchRoutineStepsTest are ported. Not like Kotlin: the window's
   notifications are scheduled a week ahead (no receiver to re-arm exact
   alarms) and re-planned on every change and return to the app; there is no
   window widget yet (stage 6); the player has no lock-screen notification
   (as with the cardio timer).
6. **Next:** Platform: Health Connect (Android) and HealthKit (iOS) import, home-screen
   widgets, EAS Update instead of the APK self-updater.
7. EAS Build and signing for both stores.
