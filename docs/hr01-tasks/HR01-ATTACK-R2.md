## Verdict

**Open-ended.** The rule at [2-HR01-COMMON.md:161](/Users/mirzohidkhon/.config/agents/state/snapshots/HR01-P1-data-453ace09-R2/inputs/2-HR01-COMMON.md:161) says that no user mark survives backup reconciliation and that a null field takes the filled row's reader result. That write bypasses the user-ownership rule at [2-HR01-COMMON.md:150](/Users/mirzohidkhon/.config/agents/state/snapshots/HR01-P1-data-453ace09-R2/inputs/2-HR01-COMMON.md:150).

AT1 proves the gap by inspection. The backup holds a blank round, a user mark, and the reader's old 150 bpm. Replace followed by reconciliation erases the mark and writes 150 bpm, even with Health Connect off. The restore needs the same deny-by-default ownership check as a read commit.
