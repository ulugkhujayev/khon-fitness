Notes for Part C:

- Generation: `KhonRepository.generation` (in memory, `AtomicLong`). It is raised by the `inside` lambda that `KhonDao.importBackup(b, replace, inside)` and `KhonDao.resetToSeed(inside)` run first in their transactions; `importJson` passes it for Replace and Merge. A heart rate commit reads `repo.generation` when it begins and compares inside its transaction, as `commitTimerRun(r, current)` does. Keep the `inside` call when the merge rules change `importBackup`.
- Timer end: `KhonRepository.endTimerRun(generation, ended)` is the one place; it runs under the private `timerLock`, which also wraps `replacingTimer` (Replace and reset). The phase 2 import lock can be this lock. A Merge import does not take it and does not stop the timer.
- Holding a timer commit in a test: set `repo.beforeTimerCommit = { reached.complete(Unit); release.await() }`. It runs after the generation is read and before the lock, so a Replace or Merge can run while it waits (C17a). See the `Hold` class in `TimerCommitTest`.
- Service helpers: `recordRun(repo, context, state, generation)` and `commitPending(repo, context)` (`TimerService.kt:461`, `:467`) are what the service runs; the tests call them with a Robolectric context.
- `TimerRunResult`, `TimerCommit`, `EndedRun`, `TimerControl`, `TimerStart` are in `data/TimerCommit.kt`.
